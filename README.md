# 분식왕 야장 – Cloudflare 멀티플레이 배포 가이드

구조: **Workers(접속·정적 화면)** → **Durable Object `GameRoom`(실시간 공용 공간, WebSocket 하이버네이션)** → **DO SQLite 저장소(플레이어 재화·재료·닉네임)**.
화면(`public/`)은 Workers Static Assets로 배포되어 요청이 무료·무제한입니다. 방 이름은 `/ws?room=이름` 으로 확장할 수 있어요(기본 `main`).

## 1. 배포 (PC 터미널, 3줄)
```bash
cd bunsik-cf
npm install                # wrangler 설치
npx wrangler login         # 브라우저가 열리면 Cloudflare 로그인 → Allow  (토큰을 파일에 적지 않습니다)
npx wrangler deploy        # name=fancy-wave-fd38 로 기존 Worker 위에 배포 + DO 마이그레이션(v1, SQLite) 적용
```
배포가 끝나면 `https://fancy-wave-fd38.od1324.workers.dev/` 로 접속합니다. (서브도메인 `od1324`는 계정 고유값이라 그대로 사용)

- 이 Worker를 대시보드에서 만들 때의 기본 "Hello World" 코드는 **덮어써집니다**. (정상)
- Free 플랜은 SQLite 기반 DO만 허용 → `wrangler.jsonc`의 `new_sqlite_classes`가 그 설정입니다. 유료 전환/결제 수단 등록은 필요 없습니다.
- 로컬 테스트: `npm run dev` → http://localhost:8787 (탭 두 개로 손님/요리사 테스트), 서버 규칙 테스트: `npm test`.

## 2. 서버가 검증하는 것 (클라이언트는 "요청"만 보냄)
| 항목 | 서버 검증 |
|---|---|
| 이동 | 최대 속도(초당 11칸+여유) 초과 시 위치 되돌림, 맵 범위 제한 |
| 앉기 | 자리 근처인지, 이미 찼는지 |
| 주문 | 앉았는지, 메뉴가 구역에 맞는지, 돈 충분한지, 한정 모찌 시간 |
| 조리 | 조리대 근처, 재료 보유·소모, **정지 타이밍을 서버 시계로 판정**(PERFECT/GOOD/NORMAL/FAIL) |
| 서빙 | 주문한 메뉴와 일치, 거리, 중복 서빙·중복 지급 차단, 요리사 보상 서버 계산 |
| 결제 | 식사 시간 경과, 키오스크 근처, 중복 결제 차단 |
| 보상 | 청소·호객·인사·요리쇼·버스킹 쿨타임, 수확(밭 근처·익은 작물만), 채소 판매(양쪽 잔액 검증) |
| 채팅 | 닉네임·직업은 서버가 부착, 도배 방지, 욕설 가림 |
| 접속 | 닉네임 중복 방지(오프라인 닉네임도 예약), 같은 ID 재접속, 100명 제한, 퇴장 시 주문 정리 |

## 3. 무료 한도 (2026-10 확인한 Cloudflare 문서 기준 — 변경될 수 있으니 대시보드에서 재확인)
- Durable Objects 무료: **요청 10만/일**(WebSocket 수신 메시지는 20개당 1요청, 송신·핑은 무료), 기간 13,000 GB-s/일, SQLite 읽기 500만 행/일·쓰기 10만 행/일·저장 5GB.
- 한도를 넘으면 **요금이 청구되지 않고 해당 작업이 실패**합니다(매일 00:00 UTC=한국 오전 9시 초기화).
- 이 프로젝트의 절약 장치: 이동 4Hz·**움직일 때만** 전송, 서버 50~150ms 묶음 전송, 핑은 자동응답, 접속자가 조용하면 DO 하이버네이션, 저장은 퇴장 시에만(+닉네임 예약 1회).
- 추정: 움직임 40% 기준 플레이어 1명 ≈ 시간당 약 330 요청 → **하루 약 300 플레이어·시간**. (예: 50명이 6시간, 100명이 3시간)
